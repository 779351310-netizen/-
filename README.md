# 情侣厨房

只给两个人使用的微信点餐小程序，采用温柔的粉色卡片风格，参考仓库外提供的界面示意图。

## 已包含

- 两人配对：一人创建厨房，另一人用邀请码加入；后端按微信 OpenID 校验成员。
- 厨房与吃货角色切换。
- 菜品分类、菜品描述、制作时间和手机相册/相机图片上传。
- 点餐、备注、订单历史和制作状态：待制作 → 制作中 → 已做好 → 已完成。
- 已做好状态在订单页内可见；可选微信一次性订阅消息提醒。

## 重要说明

仓库里的代码本身不限制谁能查看；小程序的数据访问由 CloudBase 云函数检查，只允许配对成员读取和修改。不要把 AppSecret、云函数密钥或个人凭证提交到 GitHub。

Codex Cloud 环境和微信 CloudBase 环境是两回事：前者只用于 Codex 准备代码工作区；运行小程序还需要微信小程序 AppID 和一个微信云开发环境。

## 在微信开发者工具中运行

1. 创建微信小程序并准备 AppID；在微信开发者工具中导入本仓库根目录。
2. 在项目设置中用你的真实 AppID 替换 project.config.json 中的 touristappid。
3. 在 miniprogram/config.js 填入 CloudBase 环境 ID。
4. 在微信公众平台启用云开发，并把小程序 AppID 关联到该 CloudBase 环境。
5. 在 CloudBase 中启用云函数、数据库和云存储。把 cloudfunctions/orderApi 部署为云函数，并选择“云端安装依赖”。依赖为 wx-server-sdk 3.0.1。
6. 首次运行时，云函数会按需创建 couples、users、dishes、orders 集合。若当前环境不自动创建集合，请在控制台手动创建。
7. 数据库客户端权限设为禁止直接读写；小程序通过 orderApi 云函数访问数据。云存储允许已登录小程序上传文件，并关闭客户端直接读取；菜品图片由云函数在成员校验后生成临时访问地址。
8. 编译后在“我的”页创建厨房，将邀请码发给另一位使用者；对方进入“我的”页输入邀请码加入。

## 完成提醒（可选）

小程序内订单状态在刷新订单页后即可看到“饭菜做好啦”。要在小程序关闭时收到微信订阅消息：

1. 在微信公众平台申请一条订阅消息模板，并记下模板 ID 与模板字段。
2. 将模板 ID 填入 miniprogram/config.js 的 orderReadyTemplateId，以及 cloudfunctions/orderApi/index.js 的 READY_TEMPLATE_ID。
3. 如模板字段不是 thing1 与 time2，请同步修改云函数里的消息字段。
4. 在 CloudBase 关联小程序身份，并为 orderApi 云函数配置 subscribeMessage.send 权限后重新部署。
5. 配对用户在“我的”页点击“开启出锅提醒”并选择允许。微信订阅消息需用户主动授权，且模板要先获批；未配置时，点餐与订单状态功能仍可使用。

上传的菜品照片和订单数据保存在 CloudBase，不会提交到 GitHub。
